# 星港 · StarPort

[English](README.md) | 简体中文

<img src="public/icon.svg" width="64" height="64" alt="星港 · StarPort">

星港是 Codex、Claude Code、Antigravity 和 DeepSeek Harness 的本地工作台。对话、房间、共同记忆和项目要求集中在一处，各工具仍使用自己的登录、模型和权限模式。伙伴和工作流让几个 Agent 在同一个对话里协作。群聊（每个人调用自己绑定电脑上的 Agent）还在开发中。

本地对话工作台与多人群聊：统一管理四种 Agent 和本机 Ollama 模型，手机通过可安装 PWA 调用绑定电脑上的工具，使用调用者自己的模型登录与额度。

本地工作台不需要星港账号。群聊使用你所选服务器上的账号；模型凭据留在每位参与者自己的电脑上。星港不提供模型订阅，也不在厂商之间转移凭据。

## 亮点

- **提示词随手插入。** 把常用的提示词存起来。发送键旁的 **提示词** 会列出它们，选一条就插到光标处。同一个菜单还能把已经输入的内容存成新提示词，以及重命名、调整顺序和删除。
- **记忆由你自己管。** 四个工具共用一份记忆，不依附任何厂商账号。模型只能提出候选，你确认之后才会记住。条目可以自己添加、修改、搜索和删除；个人偏好和各项目的要求分开管理。每条回复下方的回执会列出这次请求拿到了哪些条目。
- **旧对话一起带过来。** 导入本机的 Codex 历史，也支持 Claude Code、Antigravity 和 DeepSeek，标题、工作文件夹和工具调用记录一并带上。之后在星港里用任何工具接着聊，换工具不用从头再来。

## 开始使用

### Windows

1. 安装 [Node.js 24 或更新版本](https://nodejs.org/)（包含 npm）。安装后重新打开终端或启动入口。
2. 在仓库页面选择 **Code → Download ZIP** 并完整解压，或用 **Code** 菜单里的地址克隆仓库。
3. 双击项目文件夹里的 **Start StarPort.cmd**。首次启动需要联网安装锁定版本的依赖；以后启动会复用。
4. 安装并登录你要用的 Agent 工具。**设置 → 连接与数据** 会显示星港找到了哪些工具，也可以填写程序路径。

工作台地址是 **http://127.0.0.1:3210/**。请在解压后的文件夹里运行启动入口，不要直接在 ZIP 里运行。正常使用不需要 Python，也不需要另外下载 MAGI。

新安装默认使用英文。**设置 → 通用 → 界面语言** 可切换为中文，已保存的选择会保留。只有界面文字会变；你的消息、名称、文件名和工具输出保持原文。

### macOS

要求：macOS 14 或更新版本、Node.js 24 或更新版本，以及 Apple Command Line Tools。如有需要，用 `xcode-select --install` 安装。

```sh
npm ci
npm run install:macos
```

安装器默认在 `~/Applications` 生成 **StarPort.app**。已有安装（包括旧的本地化应用名）会被识别并沿用。从访达或 Dock 打开应用；用 **File → New Window** 或 `⌘N` 打开另一个窗口。关闭窗口不会停止后台任务。详见 [Mac 独立窗口](docs/zh-CN/macos-desktop.md)。

### 手动启动：Windows、macOS 或 Linux

```sh
npm ci
npm run launch
```

每台电脑都需要自己安装并登录 Agent 工具。这个仓库只包含源码、主题资源和测试，不包含对话、记忆、凭据或工具安装。要把自己的记录带过去，见 [导入、导出和换电脑](#导入导出和换电脑)。

## Agent 工具

| 工具 | 接入方式 | 星港中的选项 |
| --- | --- | --- |
| Codex | 本机 Codex App Server（JSON-RPC） | 模型、思考强度、计划与目标模式、目标预算，**请求批准** / **帮我批准** / **完全访问权限** |
| Claude Code | 官方 Claude Agent SDK 驱动本机 CLI | 模型、思考强度、工作方式（包括计划、**自动审核** 和 **跳过权限审批**）、独立 Git 工作树、审批与提问 |
| Antigravity | 本机 AGY CLI 的流式 JSON | 模型、思考强度、对话 / 编辑 / 计划模式、**允许所有工具** 或原生权限、Agent、终端沙箱 |
| DeepSeek Harness | 官方 SDK（JSON-RPC） | 模型、模型服务、思考强度；也支持桌面版自带的 CLI |

只需安装你要用的工具。模型列表和思考强度都来自各工具。星港无法确认某个模型支持什么时，会直接说明，不做猜测。权限选项对应工具自己的模式，原工具仍可执行自己的规则或要求批准。选择工作文件夹并不会建立操作系统级沙箱。

在审批卡片上可以允许或拒绝操作、回答问题，或跳过问题而不授予权限。**查询剩余用量** 显示各厂商自己接口报告的内容，缺少的字段不做估算。星港启动的 Antigravity 会话默认 **允许所有工具**；如需沿用 Antigravity 自己的规则，在 **工具权限** 里选 **遵循原工具权限**。

- **点名**：在输入框里 `@伙伴`。只点一位时直接交给它；一条消息点了几位时，先由排程模型排出执行顺序（可以有先后，例如一位做完再由另一位验收），再按顺序运行。排程模型在 **设置 → 工作流** 里设三个，第一选不通用第二选，再不通用第三选；都不通时按原话里的先后顺序。每位伙伴在每个对话里有自己的工位会话，换了对话就从零开始。
- **谁接这条消息**（功能测试中）：一条消息只要点名了伙伴，就整条交给伙伴，对话模型不处理它；不点名的消息才交给对话模型。想让对话模型在同一条消息里也做一部分，写 `@主模型`（或点输入框里的「主模型」按钮），后面接它那部分。主模型和伙伴一起排进执行顺序：比如「@甲 查资料，@主模型 等甲查完后汇总」，甲先做；主模型拿到甲的产出后，在对话里照常回答，用的是它自己的会话、工具和审批。对话模型正在回答别的消息时，它这部分排队等候。只写 `@主模型`、不点伙伴，就是一条普通消息。
- **单向可见**（可选，按对话记住）：点名时输入框里会出现「单向」开关。打开后，伙伴只收到这条消息（以及同一次点名里排在它前面的伙伴的产出），看不到对话的标题和之前的内容，并且在另一个单向工位里工作，不会带上普通工位记得的对话；它的回答照常作为卡片回到对话，对话模型能看到，也能用历史工具读取单向工位的完整记录。之后的普通点名会补上这些单向回答。伙伴和对话共用工作目录，「不读 `.starport/history` 下的对话存档」只是写在指令里的要求，不是技术隔离；长期记忆仍按房间里的记忆开关。
- **同时工作**（功能测试中）：伙伴工作时，可以接着点名其他伙伴并行工作，也可以不点名、直接和对话模型说话。再点名同一位伙伴时，新请求排队，卡片和右栏显示「排队中」，轮到时才开始计时。右栏伙伴旁的已工作时长每秒更新，不用点开卡片。
- **考场**：让伙伴在没有上下文的独立空间里盲做同一道题。对话模型用 `starport_exam_propose` 出题：指定试卷文件夹、题目说明、考位（同一位伙伴可以坐几个考位）、可选的知识库和每个考位的时限；对话里随即出现一张「待开考」卡片，这时什么都还没复制。你核对后可以增减考位、逐个设开卷或闭卷、改时限，再按「开考」；不按就不会开考，也可以取消。开考后试卷复制到桌面 `StarPortExams` 下的新文件夹，每个考位一份（`.git` 不复制），开卷的考位另有 `知识库/`；各考位同时作答，每位考生在新会话里只收到考场规则和题目说明，看不到这个对话、长期记忆、星港里的个人偏好和其他考位（各工具自己的全局指令，例如 `~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`，仍会照常加载）。交卷后检查每个考位：试卷文件有没有被改、删，新增了哪些文件，工具调用有没有碰到原工作区、试卷原件、知识库原件、星港数据目录或其他考位。所有答卷和检查结果作为考场卡片回到对话，对话模型能看到，也能用历史工具读取每个考位的完整记录。考位不是沙箱：越界只能事后查出来，不能事前挡住。
- **工作流**：可复用的流程模板，由阶段和位置组成。同一阶段的位置并行，下一阶段能看到上一阶段的产出；可以设验收位和验收不通过时的重做次数（0–3）。工作流在「工作流库」里管理，可以挂到任意房间的对话上；挂载时决定每个位置坐哪位伙伴，房间外的伙伴会自动加入房间，位置空着时工作流暂停。
- **触发方式**：只在点它时、每天定时（可选星期）或每隔一段时间。定时器在星港服务里运行，关掉浏览器照样会跑，星港没开时不会跑；错过的运行可以设成开机后补跑一次或跳过。
- **运行卡片**：每次运行在对话里追加一张卡片，完成的默认折叠，失败或验收不通过的会展开。卡片上可以停止运行、查看每一步的过程，或者「回复」，下一条消息就会带上这次运行的结果。每次运行，各位置都在新的工位会话里从零开始，不读这个对话的历史。
- **台账**（可选，默认关闭）：工作流在多次运行之间的笔记本，按 Anthropic 长时间运行任务的做法分为 PLAN、命题、只追加的 CHANGELOG 和检查项，每次运行提交一次 git。伙伴只能提议修改 PLAN，要你确认才生效；带截止日的预测用 Brier 分数计分。台账放在工作文件夹的 `.starport/ledgers/`，同一文件夹里挂同一工作流的对话共用一份。对话更换文件夹时，原台账留在原处，之后使用目标文件夹的台账，没有则在运行工作流时新建；旧版数据目录中的私人台账也不自动搬迁。
- **长期记忆**：在「伙伴进出」里，每个房间的每位伙伴各有「读长期记忆」（默认开）和「提记忆候选」（默认关）两个开关。伙伴提出的候选只能引用你的原话，仍要你确认才会保存。
- **干活时调用伙伴**（功能测试中，默认全关）：同样在「伙伴进出」里，按房间勾选主模型和每位伙伴「可以调用」谁，例如主模型可以调用甲和丙、不能调用乙，乙可以调用丙。被允许的一方在做事过程中自己判断要不要把一部分交出去：它交代任务，被调用的伙伴在一个新工位上做（看得到对话进展，看不到调用方的思考），结果交回调用方，对话里同时出现一张「X 调用 Y」卡片。几件事可以同时交出；嵌套最多三层，调用链上已经在等结果的伙伴不会再被叫回来，所以不会循环。调用方这一轮结束时还没做完的调用会被停止；被调用的伙伴连续 30 分钟没有任何活动（只看有没有动静，不看总时长）也会被停止，并以失败交回调用方；这些卡片不单独弹完成提醒。被调用的伙伴照常无人值守，用它自己的模型和额度。改了某个对话主模型的调用范围后，下一轮会用星港保存的历史开一个新的原生会话。
- **房间默认工作目录**：在房间菜单里选「默认工作目录…」，或在房间里某个对话的菜单里点「设为房间默认工作目录」，把那个对话现在的工作目录设成房间默认。之后在这个房间新建的对话，默认在这个目录下工作；已有对话的工作目录不变。鼠标停在房间名上可以看到当前的默认目录；不想用了，在房间菜单里点「不再使用默认工作目录」。
- **知识库**（功能测试中）：可以给房间（房间菜单 →「知识库…」）、对话（对话菜单）或伙伴（伙伴设置）挂本机文件夹作为参考资料。每一轮会读它所在房间和这个对话的知识库；伙伴干活时还会读它自己的。考位和星港自己的工位（压缩、排程）不读。文件夹留在原处，不复制：模型拿到路径和顶层目录，需要时用自己的工具查阅。知识库是只读的：Claude 把它们作为额外的工作目录，但禁止编辑，沙箱终端也只能读；Codex 的沙箱本来就能读工作目录以外的文件，但不能写（完全访问权限除外）；agy 用 `--add-dir` 加入，Antigravity 和 DeepSeek 只靠提示要求不写；Ollama 读不了文件。续接的原生会话只在列表变化时重新告知。包含工作目录的知识库文件夹在那一轮会被跳过；整个磁盘、用户主目录、星港数据目录和登录凭据目录不能设为知识库。要往知识库里加东西，就在对话里明确说，比如「把这篇论文下载到房间知识库」。模型会调用 `starport_knowledge_save`，由星港自己把网址下载下来（http/https，最大 500 MB，不能从本机地址下载），或者把工作目录里的文件复制进指定的知识库；同名文件不会被覆盖，除非明确要求。你这一轮的消息里没有提到知识库（知识库、资料库、knowledge base、reference material）时，存入会被拒绝，下载和生成的文件照常写进工作目录。对话自己的模型可以存进房间、这个对话和房间里伙伴的知识库；在对话里被 @ 的伙伴可以存进房间、这个对话和它自己的知识库。被调用的伙伴、工作流步骤和考位不能存。Codex 只在会话开始时登记工具，所以 Codex 对话第一次有地方可存时，会重新开一个原生会话。
- **Antigravity 中途停下时接着做**（功能测试中）：agy 遇到单次回复超出输出上限、流或连接中断时，会在同一轮里自己重试，但最后仍会报出那条错误。重试后写完了完整最终回复的一轮算完成。如果无人值守工位上的 Antigravity 伙伴（被调用、考位、@伙伴、工作流）确实因为这些原因中途停下，星港会恢复同一个 agy 会话请它接着做，最多两次，每次都在卡片上注明。主模型不会自动接着做。

详见 [Agent 工具：模型、权限与用量](docs/zh-CN/agents.md)。

## 对话

- 侧栏的 **房间** 用来整理对话。同一个房间里的对话可以使用不同的文件夹、工具和模型。房间和房间里的对话都可以拖动，按你的顺序排列。
- 工作文件夹就是项目。同一文件夹里的对话共用项目要求和项目记忆；子文件夹是独立的项目。在输入框下方的文件夹选择器里选择或重命名文件夹。
- **执行过程显示** 决定任务过程显示多少：**隐藏**、**概览** 或 **完整**。任务进行中概览保持展开，结束后收进 **查看任务过程**。子代理显示在所属回复里面。星港只显示工具实际报告的内容，不补写未公开的思考。
- 转圈表示对话正在运行，有伙伴在为它工作时也算；蓝点表示有已完成但你还没看的回复。失败、已停止和未确认结束分别显示。
- 任务进行中发出的消息进入 **等待队列**，可以修改或删除。Codex 和 Claude Code 可以用 **引导** 把排队的消息交给正在运行的任务。排队的消息可以带附件。任务不会仅仅因为没有动静而被停止。
- 已结束回复下方的 **从这里分支** 会新建一个对话，带上到这条回复为止的记录。发送键旁的 **提示词** 可以插入你保存的提示词。每个代码框都有 **复制** 按钮，复制的是原始文本。
- 输入框下方的 **上下文** 显示 Codex 或 Claude Code 最近报告的上下文占用。

## LaTeX 编辑器（功能测试中）

点顶栏的 TeX 文档图标，在当前对话旁边打开 LaTeX 编辑器：左边是源码，右边是用本机 TeX 编译出的 PDF。编辑器可以停在对话左边或右边（拖动边线调宽度），也可以单独开一个窗口；每个对话记住自己的位置。

- **主文件**：第一次打开时，从工作目录里含 `\documentclass` 的 `.tex` 文件中选一个。之后从这个对话打开都直接进入它；文件菜单里可以换主文件、打开同一项目里的其他文件。
- **保存与编译**：停笔约一秒自动保存到磁盘，保存后自动编译（可以关掉「自动」，改按 Ctrl S 或「编译」）。引擎自动判断：开头写了 `% !TEX program = xelatex` 就用它；用了 ctex、fontspec 等用 XeLaTeX；否则用 pdfLaTeX。编译输出放在工作目录的 `.starport/latex/` 里，源码旁边不会多出辅助文件。
- **错误与跳转**：错误和警告列在底部，点一条跳到对应的文件和行，源码里也会标出。双击 PDF 跳到对应的源码；「定位到 PDF」（Ctrl Alt →）在 PDF 里标出光标所在的位置。
- **可视模式**（工具栏的「可视」，默认打开）：文件仍是标准 `.tex`，只是显示变了。公式用 KaTeX 就地渲染，读取你导言区的 `\newcommand` 等宏，也支持 physics 宏包的常用命令，编号是上次编译的真实编号，不需要 `\label`；TikZ、Feynman 图用本机 TeX 配你的真实导言区单独编译后显示；标题、粗体、斜体直接显示效果；`\ref`、`\eqref`、`\cite` 显示上次编译的真实编号；`\includegraphics` 显示图片。光标移到哪里，哪里就变回源码，改公式或改图时下方有实时预览。KaTeX 画不了的公式保留源码；依赖正文里宏的图，会从编译好的 PDF 里裁出来显示。
- **和模型、伙伴配合**：在编辑器里框选一段源码，输入框上方出现虚线的引用卡片，取消选中它就消失。要同时引用几处，按 Ctrl L 或点卡片上的图钉把这段留下（变成实线），再去框选别处；留下的卡片在发送或点 × 之前一直都在，刷新页面也不丢。发消息时这些源码附在你的话前面。编辑器开着的时候，主模型每轮都会知道主文件、你正在看的文件和小节，以及上次编译的结果。模型或其他编辑器改了磁盘上的文件，编辑器会自动载入、标出改动的行并重新编译；你这边也有没保存的改动时，会让你选保留哪个版本。
- **编译权限**：TeX 使用当前用户权限运行。星港跳过项目的 latexmk 配置，并使用 TeX 的受限 shell escape。文件读取限制取决于本机 TeX 发行版，无法保证只读取项目内的文件，请只编译可信源码。LuaLaTeX 需要在编辑器中授权，可在文件树底部撤销授权。TikZ 图直接画进 PDF。
- 需要本机装有 TeX Live、MiKTeX 或 MacTeX。找不到 `latexmk` 时，可以把它所在的 bin 文件夹填进环境变量 `STARPORT_TEX_BIN`。只支持 UTF-8 编码的源码文件。

## 划词翻译与朗读（功能测试中）

在对话里选中一段文字，旁边会出现「翻译/解释」和「朗读」。

- **翻译/解释**：在选中处下方弹出小框显示结果。每次点击都新开一个隐藏对话，模型只收到提示词和选中的文字，不带对话记录、记忆或星港的要求。默认用 Antigravity 的 `gemini-3.8-flash-low`，提示词是「用三句话解释这个词语/短语/句子」。**设置 → 划词** 可以换工具、模型和提示词，也可以用本机 Ollama 模型。原工具自带的系统提示和全局文件（如 `CLAUDE.md`、`GEMINI.md`）仍可能生效。
- **朗读**：用浏览器自带的语音，按文字语言选声音。朗读时页面顶部显示「正在朗读」和「停止」按钮。

划词工具可以在 **设置 → 划词** 里关闭，只影响当前设备。

## 长对话的上下文

同一个工具接着聊时，Claude Code、Codex 和 Antigravity 续用自己的原生会话，压缩由原工具负责。需要新会话从头读历史时（换了工具或模型、开了分支、改了对话设置，以及每轮都是新会话的 DeepSeek 和 Ollama），历史太长就会自动压缩：由写摘要的模型把较早的对话整理成结构化摘要（逐条保留你的原话要点），模型拿到的是摘要加上之后的原文。摘要属于对话，换模型时直接复用，只有新内容又放不下时才再压缩一次。压缩进行中，对话区和底部状态会显示「正在压缩上下文…」。

没有直接交给模型的原文另存为工作目录下的 `.starport/history/<对话id>.md`，开着沙箱的工具也能读到；`.starport/` 自带 `.gitignore`。**设置 → 上下文** 可以开关自动压缩、按工具设定新会话最多读入多少历史（默认 Codex、Claude、Antigravity 各 10 万 token，DeepSeek、Ollama 各 6 万 token），以及选三个写摘要的模型。交给 Antigravity 的单次输入另限 184,000 字节，这是星港为避免输入被截断设的保护值。

## 五个适配器

| 工具 | 实际接入方式 | 当前选项 |
|---|---|---|
| Codex | 原生 App Server / JSON-RPC | 模型、思考强度、原生计划与目标模式、目标预算、请求批准 / 帮我批准 / 完全访问权限 |
| Claude Code | 官方 Agent SDK 驱动本机 CLI | 模型、思考强度、计划模式、编辑策略、Git 工作树、权限审批与提问 |
| Antigravity | 官方 CLI / stream-json | 模型、思考强度、只读或编辑模式、允许所有工具 / 原生权限、Agent、终端沙箱 |
| DeepSeek Harness | 发布版官方 SDK / JSON-RPC | 模型、服务、思考强度；默认从 Harness 的模型设置中读取 |
| Ollama（功能测试中） | 本机 Ollama HTTP API | 已下载的本地模型；模型支持时可开关思考 |

Windows 的 DeepSeek Harness 桌面版可在原工具中启用 `dsh` 命令。星港会识别 PATH 中的官方 `resources/runtime/cli/bin/dsh.cmd`；若星港在启用命令前已启动，可在「连接与数据」中填入该文件的完整路径。星港直接使用桌面版自带的运行时与已有登录，无需再装一份 CLI。桌面版模型偏好作为默认值，SDK profile 中明确保存的偏好优先；每轮仍使用独立 SDK 会话。DeepSeek 账号登录的额度请在原桌面版查看，它与开放平台 API 余额不同。

Ollama 只做文字问答：不读写文件、不运行命令，也不调用星港工具，每轮由星港附带对话记录。它连接本机的 Ollama 服务（默认 `http://127.0.0.1:11434`，可用 `OLLAMA_HOST` 修改），模型需要先在终端用 `ollama pull` 下载。群聊里不提供 Ollama。

思考强度随工具和具体模型变化。Claude 与 Codex 从原生模型目录读取支持的档位，Claude 的 `xhigh` 显示为 **Extra**；DeepSeek 从已安装的适配器读取档位（包括 **Off**）；Antigravity 使用其 CLI 提供的 Low / Medium / High。模型默认只标注已确认的基础档位，不覆盖原工具保存的偏好。Claude SDK 尚不返回精确的用量倍数，因此 Max 显示用量增加提示，不固定声称所有模型都消耗 6 倍。

*（功能测试中）* Claude 单次回复（含思考）最多 128000 token，这是所有现有模型的硬上限，`CLAUDE_CODE_MAX_OUTPUT_TOKENS` 也调不高；思考在这之前没有写出文字或调用工具，就会被整段丢弃。工具调用之前的思考会保留，下一次回复重新计算上限。因此星港给每次 Claude 调用加了一个只读的「阶段记录」工具（`mcp__starport_thinking__checkpoint`，不需要审批），并说明：一段思考已经很长、还没到作答时，先记下已经得出的结论、未解决的问题和下一步，再接着想。这样分段之后，总的思考长度不受单次上限限制，也不要求它想得更短。

模型选择「跟随工具默认」、自定义模型或读取失败时，如果无法确认该模型的能力，只提供跟随默认并说明原因；选定具体模型可显示对应列表。切换模型不会偷偷降低已保存的强度：不兼容的旧档位会提示重新选择，发送前再次校验。工具升级后点击模型旁的「刷新列表」重新读取。各个工具的选择独立保存。DeepSeek 的第三方服务只有明确配置了 `reasoningEfforts` 时才展示自定义档位。

Antigravity 自动发现顺序为明确配置、当前 PATH、用户标准安装目录、星港内置副本。查询用量与对话沿用原工具的本地登录环境，不注入 SSH 标记；否则原工具可能改用不同的凭据存储。

安装状态和真实连接验证分别显示。程序已安装和账号可正常调用是分别检查的状态；新电脑需使用原工具自己的登录方式。

没有原文发送的消息保存在工作文件夹里的 `.starport/history/<对话 id>.md`，模型可以读取；`.starport/` 自带 `.gitignore`。**设置 → 上下文** 可以开关自动压缩、设置每个工具的预算（默认 Codex 和 Claude Code 各 10 万 token，Antigravity 和 DeepSeek 各 6 万 token），并选择最多三个写摘要的模型。发给 Antigravity 的每次请求另限 184,000 字节，避免输入被截断。

## 共同记忆与项目要求

星港的记忆独立于厂商账号，四个工具共用。它支持提取候选、确认、在新请求开始时检索，以及在任务中追加检索。个人偏好和项目要求分开管理。

候选需要确认后才成为共同记忆。记忆按与当前请求的相关程度选取，不预设话题列表。模型可以查看候选索引、读取选中的条目，需要更多细节时再检索相关历史。

回复下方的记忆链接会打开这次请求的回执：提供了哪些条目、产生了哪些新候选。它不会把整个记忆库当作全部用过来展示。

- [共同记忆](docs/zh-CN/shared-memory.md)
- [检索架构](docs/zh-CN/memory-retrieval.md)
- [在电脑之间同步记忆](docs/zh-CN/memory-sync.md)

*功能测试中。* 在自己的几台设备之间同步时，选择由你已有的同步服务管理的对应文件夹，例如坚果云、OneDrive 或 Syncthing。星港会创建 `StarportMemory` 子文件夹，运行期间每 15 秒检查一次。已确认记忆、候选、用户画像和已保存的要求可以同步；聊天、附件、登录和工作文件夹留在本地。冲突时保留双方版本供核对。请使用私有的同步文件夹，因为这些文件包含记忆正文和修改历史。

## 房间、伙伴与工作流

房间里还可以住进 **伙伴**：有名字、头像、角色、性格、工具、模型、思考强度，以及无人值守时的工作方式（工具的原生权限模式）。性格只改变伙伴对你说话的语气，不影响它的分析。一位伙伴可以加入任意多个房间。

- **点名**：输入 `@名字` 把任务交给伙伴。只点一位时直接交给它。一条消息点了几位时，先由排程模型排出顺序，例如一位做事、另一位验收。**设置 → 工作流** 里设三个排程模型，依次尝试；都没有响应时按消息里的先后顺序。每位伙伴在每个对话里有自己的工位会话。
- **单向可见** *（功能测试中）*：伙伴只收到这条消息，以及同一次点名里排在它前面的伙伴的结果，看不到对话历史。它的回答照常回到对话里。这是写在指令里的要求，不是技术隔离，因为伙伴和对话共用工作文件夹。
- **同时工作** *（功能测试中）*：伙伴工作时，可以接着点名其他伙伴并行工作，也可以不点名、直接和对话模型说话。再点名同一位伙伴时，新请求排队，卡片和右栏显示「排队中」，轮到时才开始计时。右栏伙伴旁的已工作时长每秒更新，不用点开卡片。
- **`@主模型`** *（功能测试中）*：一条消息只要点名了伙伴，就整条交给伙伴。在某一部分前面写 `@主模型`，这部分就交给对话自己的模型，它和伙伴一起排进执行顺序，例如等某位伙伴做完再汇总它的结果。
- **干活时调用伙伴** *（功能测试中，默认关闭）*：按房间勾选主模型和每位伙伴干活时可以调用谁。被允许的一方把一部分任务交给伙伴，伙伴在新工位上做完后交回结果，对话里出现一张「X 调用 Y」卡片。嵌套最多三层，不会循环。
- **工作流** 是由阶段和位置组成的可复用模板。同一阶段的位置并行运行，下一阶段能看到它们的结果。验收位可以把工作退回，最多重做三次。在 **工作流库** 里管理工作流，再挂到任意对话上，为每个位置选一位伙伴。房间外的伙伴会自动加入房间。
- **触发方式**：手动、每天定时（可选星期）或每隔一段时间。定时在星港服务里运行，关掉网页不会停止，但服务没开时不会运行。错过的运行可以补跑一次或跳过。
- **运行卡片** 把每次运行记录在对话里。展开卡片可以跟进每一步、停止运行，或点 **回复**，让你的下一条消息带上这次运行的结果。每次运行都从新的工位会话开始，不读对话历史。
- **台账** *（功能测试中）*（可选，默认关闭）在多次运行之间保存笔记：PLAN、命题、只追加的 CHANGELOG 和检查项，每次运行后提交到 Git。伙伴只能提议修改 PLAN，你确认后才生效。带截止日的预测用 Brier 分数计分。台账放在工作文件夹的 `.starport/ledgers/`，同一文件夹里挂同一工作流的对话共用一份。
- **考场** *（开发中）* 让伙伴在没有对话上下文的情况下各自独立做同一道题。对话模型用 `starport_exam_propose` 提出考试；在你核对提议并点 **开考** 之前，什么都不会复制。每个考位在桌面的 `StarPortExams` 下得到一份自己的试卷，开卷的考位还附带知识库。交卷后星港检查每个考位：哪些文件被改或新增，有没有工具调用越出自己的文件夹。考位不是沙箱：检查只能事后发现问题，不能事前阻止；各工具自己的全局指令也仍会加载。
- **记忆**：在每个房间里，每位伙伴有两个开关：**读长期记忆**（默认开）和 **提记忆候选**（默认关）。伙伴提出的候选必须引用你的原话，仍要你确认。

详见 [房间、伙伴与工作流](docs/zh-CN/rooms-and-workflows.md)。

## 通知与设置

任务完成或出错时，星港会显示一条通知，包含房间、对话标题和简短摘要；点击即打开该对话。在 Windows 上是原生弹窗并响一声短提示音，星港在后台时任务栏按钮会闪烁；其他系统使用浏览器通知。点名伙伴的消息要等点名的所有人都做完，才提醒一次。你正在看的对话、你手动停止的任务，以及还有排队消息的任务不提醒。顶栏的铃铛用来开关 **勿扰模式**。

**设置** 汇集全局选项：**通用**（语言和主题）、**通知**（提示音和测试通知）、**工作流**（排程模型、重做次数和单步时限）、**上下文**（压缩和预算）以及 **连接与数据**（工具位置、本机服务器和备份）。

### 查询剩余用量

右侧「当前工具」点击 **查询剩余用量**。小窗口先点击右上角「☷」展开工具选项。弹窗可切换五个工具、刷新查询，并展开「完整厂商报告」。支持中英文，显示查询时间；无数据、未登录和失败会明确说明，不显示其他账号的历史查询结果。

| 工具 | 查询内容和来源 |
|---|---|
| Codex | 原生 `account/rateLimits/read`：各限额桶、剩余比例、窗口重置时间、额外额度和可用重置次数，保留原生返回的其他限额字段 |
| Claude Code | 官方 SDK 的原生 `/usage` 报告：订阅、会话/周/模型限额、额外用量与支出、本机用量归因 |
| Antigravity | 原生 `/usage` 和 `/credits` 文本报告，保持原厂格式；需已登录 CLI，其登录与 IDE 分开 |
| DeepSeek Harness | 官方服务 `/user/balance`：可用状态、总余额、赠送余额和充值余额，保持原始币种和金额精度；第三方服务需在该服务查询 |
| Ollama | 本机运行，没有账号额度；显示已加载的模型（`/api/ps`） |

打开 **群聊与手机**，选择服务器并登录该服务器上的账号。群主分享服务器地址和邀请码。每个人连接自己的电脑，并选择开放哪些文件夹和工具。

参与者可以互相聊天，也可以在群里调用 Agent。共享的回复全群可见；只有调用者本人能答复自己的审批或停止自己的任务。调用使用调用者自己绑定的电脑和原生模型凭据，不使用其他成员的订阅。

用量 API：`GET /api/providers/{codex|claude|antigravity|deepseek|ollama}/usage?workspace=绝对目录`，沿用本地令牌和同源校验。DeepSeek 可附加 `service` 参数，与已选服务一致；自定义服务凭据不会发给官方地址。Claude SDK 用量方法目前为实验接口，版本不兼容时明确报错，升级后需验证。

## 文件、网页与字幕

输入框下方的 **＋** 菜单可以附加文件、文件夹、浏览器标签页和视频字幕，还包含 **在项目中工作**、Codex 的 **目标**、**计划模式** 和 **绘图** 画布。文件保存为本地副本，每个最多 8 MB，每条消息最多 16 项、合计 24 MB。文件夹以路径附加，不会复制。文件夹浏览器显示的是运行星港服务的那台电脑上的文件夹。

可选的 [Edge 扩展](extensions/edge) 与星港配对后，可以明确附加一个浏览器标签页，或用浏览器当前的登录读取 B 站字幕。浏览器凭据留在 Edge 里。它只读取你指定的网页或视频，不读取浏览历史、密码框或无关的表单输入。缺少字幕或认证失败时会说明原因，不会编造文字稿。详见 [浏览器字幕指南](docs/zh-CN/browser-video-subtitles.md)。

回复里的本地文件链接可以用默认应用打开。在 Windows 上，右键菜单提供 **打开文件**、**在资源管理器中查看**（选中该文件）和系统的 **打开方式** 选择窗口。有歧义的相对文件名需要你选择。显示消息时绝不会执行文件操作；可执行文件和未知类型会打开应用选择窗口。

## 导入、导出和换电脑

用 **导入对话** 选择本机的 Codex、Claude Code、Antigravity 或 DeepSeek 历史，预览后选择目标房间。Codex 导入在日常使用中；Claude Code、Antigravity 和 DeepSeek 导入还在功能测试中。导入是独立副本，不是实时同步；不继承原生权限，也不会自动运行任务。工具调用作为记录一并导入，不会重新执行；隐藏的思考过程不复制。Claude 导入读取本机 CLI 历史，不读取 Claude 网页端历史。Antigravity 导入读取 `~/.gemini/antigravity-cli`，DeepSeek 导入读取 `~/.dsh/sessions`（或 `DSH_HOME`），都只读不写。星港里还在的对话不会列出，子任务和星港每轮自动开的 DeepSeek 会话也不会列出。

导出单个对话时，在它的菜单里选择 **导出对话**：

- **导出会话文件**（`.starport.json`）*（功能测试中）* 包含这个对话的消息、已有的执行记录和支持的上传附件。在另一台电脑导入，并选择本地工作文件夹。
- **导出 Markdown** 生成可阅读的记录。

会话文件不包含其他对话、共同记忆、账号登录、原生会话绑定、权限或排队任务。工作文件夹里生成的文件需要另外搬。重复导入相同内容会打开已有副本，不会覆盖其他对话。当前上限为每个会话文件 120 MB、每个上传附件 8 MB。

**设置 → 连接与数据 → 导出全部记录** 会生成星港记录的完整逻辑备份；在另一台电脑用 **导入备份** *（功能测试中）* 恢复为新副本（上限 128 MB）。导入的记忆需要核对和确认。工作文件夹、文件夹引用和浏览器连接需要在新电脑上重新设置。备份不能提交到 Git。

删除对话会移除它在星港中的记录和它自己的 `.starport/history/` 存档。附件、生成的文件、工作文件夹、原工具里的历史、导出和备份都会保留，相关内容需要另行检查和删除。普通删除不会自动压缩数据库，也不承诺不可恢复的擦除。

## 本地存储与维护

本地工作台使用 WAL 模式的关系型 SQLite 表。主数据库是 `.data/hub.sqlite`；单个数据库文件是 SQLite 的正常存储方式。WAL 和 SHM 文件是运行中数据库的一部分，不是可以删除的残留。详见 [数据库结构](docs/zh-CN/database-architecture.md)。

日常备份请用逻辑导出。直接复制数据库文件前，先正常停止服务，或使用 SQLite 的一致性备份功能；只复制运行中的主文件可能漏掉已提交的 WAL 数据。

Windows 辅助文件：

| 文件 | 用途 |
| --- | --- |
| `Start StarPort.cmd` | 需要时安装依赖，并启动本地工作台 |
| `Restart StarPort.bat` | 等进行中的对话结束后再重启 |
| `Clean StarPort leftovers.bat` | 明确执行的可选操作：对本地数据库做检查点和压缩 |

删除对话时不会自动运行维护工具。它不能代替逐项检查附件、工作目录或外部备份。任务进行中不要运行维护。

## 开发

要求：Node.js 24 或更新版本。Python 3.10 或更新版本是可选的，只用于安装技能和生成宿主表。

```sh
npm ci
npm test
npm start
```

测试运行器使用独立的临时文件夹，结束后清理。单个测试限时两分钟；某个测试文件五分钟内没有退出，会显示文件名并停止。只跑部分文件：`npm test -- tests/i18n.test.mjs`。推送到 `main` 或提交 Pull Request 时，GitHub Actions 会在 Windows、macOS 和 Linux 上用 Node 24 运行全部测试。

| 位置 | 职责 |
| --- | --- |
| `src/server.mjs` | 本地 HTTP 接口和静态资源 |
| `src/runner.mjs`、`src/adapters/` | 组装上下文、任务生命周期和各工具适配器 |
| `src/storage.mjs`、`src/compaction.mjs` | SQLite 记录和对话压缩 |
| `src/workflows.mjs`、`src/workflows/` | 伙伴、房间、工作流调度、台账和考场 |
| `src/external-tools/` | 项目工具授权、隔离终端、经批准的本机运行和常驻程序 |
| `public/app*.js` | 主工作台、视图、设置和交互 |
| `public/agents-room.js`、`public/room-*.js`、`public/workflow*.js` | 房间、伙伴和工作流弹窗 |
| `public/i18n.js` | 中英文界面翻译 |
| `public/mobile/`、`src/collaboration/` | 群聊与手机界面、服务和执行桥接 |
| `tests/` | 单元、集成测试和隔离界面测试 |

前端使用按顺序加载的普通脚本，没有框架构建步骤。`node tests/ui-fixture.mjs`（端口 3211）、`node tests/completion-ui-fixture.mjs`（端口 3216）和 `node tests/interactions-ui-fixture.mjs`（端口 3217）会启动使用临时数据和模拟工具的隔离服务。`node scripts/live-check.mjs codex antigravity deepseek` 会对每个工具真实调用一次模型，消耗你的额度。不要让测试连接个人账号或真实历史。

- `src/server.mjs`：HTTP 接口和静态文件；`src/runner.mjs`：调度一轮对话，组装上下文，调用适配器；`src/adapters/`：Codex、Claude Code、Antigravity、DeepSeek、Ollama 各自的适配器；`src/explain.mjs`、`public/selection-tools.js`：划词翻译/解释与朗读。
- `src/storage.mjs`：SQLite 中的分组、对话、消息和会话映射，以及上下文组装；`src/compaction.mjs`：上下文压缩。
- `src/workflows.mjs`：伙伴、房间成员、工作流和挂载的执行与调度；`src/workflows/` 下按职责拆分：`schema`（表结构）、`records`（数据校验）、`planning`（点名排程）、`prompts`（伙伴收到的指令）、`desk`（工位会话）、`ledger`（台账）、`exam`（考位文件夹的复制和交卷检查）、`cards`（运行卡片文字）、`migrate`（从旧版浏览器数据导入）、`routes`（HTTP 接口）。
- `src/external-tools/`：项目外部工具。`grants`（授权和常用工具）、`terminal`（Windows 隔离终端）、`host-run`（逐次批准的本机运行）、`applications`（常驻程序）、`processes`（启动器、环境变量和输出收集）、`claude-launch`（Claude 启动参数和私有配置副本）、`claude-tools`（提供给 Claude 的工具）、`routes`（HTTP 接口）。
- 前端是按顺序加载的普通脚本（见 `public/index.html`），同一功能拆成几个文件，共用一个全局对象：
  - 主界面：`public/app.js`（共享状态、接口调用、草稿、切换对话），`app-layout.js`（侧栏、顶栏、主题封面、面板宽度），`app-options.js`（工具、模型和思考档位），`app-messages.js`（消息、提问和运行状态），`app-send.js`（发送、引导、停止），`app-folders.js`（文件夹选择器），`app-start.js`（绑定按钮并加载第一屏）。
  - `public/ui-kit.js`：房间、工作流和提示词共用的弹窗、菜单、表单和模型选择器。
  - 工作流（`StarportWorkflows`）：`workflows.js`（数据、点名和运行、回复某次运行），`workflow-cards.js`（运行卡片和工位），`workflow-editor.js`（工作流库、编辑器、设置），`workflow-mount.js`（挂到对话），`workflow-ledger.js`（台账），`workflow-exam.js`（考场提议和考位检查）。`context-settings.js`：上下文与压缩设置。
  - 房间（`StarportAgentsRoom`）：`agents-room.js`（侧栏、右栏、输入框里的点名和工作流入口），`room-companions.js`（伙伴卡片、设置和进出房间），`room-delete.js`（删除房间），`room-migrate.js`（导入旧版浏览器里的伙伴）。
  - 主界面每次重绘后调用 `StarportAgentsRoom.scheduleRender()`，发送前先问 `routeSend()`，房间不监听主界面的 DOM 变化。

可选的工具入口用 `python scripts/install-skills.py` 安装；移动项目后重新运行。在 Codex 里调用 `$harness-hub`；在其他工具里，让它用 harness-hub 技能打开星港。入口打开的是星港自己的本地界面，不会替换原工具的界面。

星港复用了 MAGI 的宿主注册表，以及随附的 marked、KaTeX 和 Archivo 资源，并保留它们的声明。对话数据库、适配器和工作台前端由本项目实现。完整的 MAGI 仓库不是运行依赖。需要重新生成宿主表时，把固定版本的 [MAGI 2.8.0 源码](https://github.com/Misaka16384/magi/tree/e95f14a4a1601008cee9a00aa2b5e78c49842794) 放进被忽略的 `vendor/magi`，再运行 `npm run sync-magi`。

官方参考：[Codex App Server](https://learn.chatgpt.com/docs/app-server)、[Claude Code](https://code.claude.com/docs/en/headless)、[Antigravity CLI](https://antigravity.google/docs/cli/headless/)、[DeepSeek SDK](https://github.com/deepseek-ai/deepseek-harness/tree/master/packages/sdk)、[Ollama API](https://docs.ollama.com/api)。
