# 房间、伙伴与工作流

[English](../rooms-and-workflows.md) | 简体中文

房间在侧栏里把对话分组。房间里还可以住进伙伴：你命名并设置一次，之后就能在这个房间的任何对话里调用的 Agent。工作流把反复要做的事变成模板，由伙伴一起手动或定时运行。伙伴、房间和工作流由星港服务保存，刷新或关闭网页都不受影响。

## 房间

在侧栏点 **新建房间** 创建房间。房间菜单可以在房间里新建对话、管理房间里的伙伴、打开工作流库，或删除房间。删除房间时，由你决定其中的对话怎么处理：移到「未分组」、导出到一个文件夹后删除，或全部删除。

侧栏右侧的 **房间** 页列出当前房间的伙伴，以及挂在当前对话上的工作流。**工具** 页保留工具、模型和选项设置。

## 伙伴

伙伴有名字、头像、角色和性格，还有工具、模型、思考强度和无人值守时的工作方式。工作方式就是工具的原生权限模式，例如 Claude Code 的 **自动审核**。性格只改变伙伴对你说话的语气，不改变它的分析和结论。

伙伴可以进出任何房间。性格和模型跟着伙伴走；它在工作流里做什么，取决于它坐的工作流位置。伙伴在无人值守的状态下工作：仍需审批的操作会被自动拒绝，它提出的问题会被跳过。请为伙伴选择能完成任务的工作方式。

每位伙伴在每个对话里有自己的工位会话。工位记得它在这个对话里之前做过的事；换到另一个对话，伙伴从零开始。打开伙伴卡片可以看到它在当前对话里做过什么。

## 点名

输入 `@` 加伙伴的名字，把任务交给它。只点一位时，消息直接交给这位伙伴，它的回答以卡片形式出现在对话里。点名暂时不能带附件。

一条消息点了几位伙伴时，先由排程模型写出执行顺序。步骤之间可以有依赖，例如一位做事、另一位验收。**设置 → 工作流** 里设三个排程模型：第一个不可用时试第二个，再试第三个；都没有响应时，按消息里出现的先后顺序运行。默认的排程模型依次是 Codex 里的 GPT-6 Luna、Antigravity 里的 Claude Sonnet 5.5（low）和 DeepSeek Harness 里的 DeepSeek Flash。请换成你能使用的模型。

同一处设置还决定点名时验收不通过要重做几次（0–3），以及每一步是否限时。默认不限总时长。连续 5 分钟没有新活动时星港会提醒，任务仍继续运行。启用单步时限后（3–240 分钟，默认 30），临近时限会提醒，到时停止该步骤，并保留已有进度和记录。修改只影响之后开始的步骤。

## 单向可见

> **功能测试中：** 还没有在实际工作中大量使用，伙伴是否真的守住这个范围也还没有检验过。

消息里点了伙伴时，输入框里会出现 **单向可见** 开关，按对话记住。打开后，伙伴只收到这条消息，以及同一次点名里排在它前面的伙伴的结果。它看不到对话标题和之前的消息，并且在单独的单向工位里工作，不带普通工位的记忆。

回答照常以卡片形式回到对话。对话模型能看到它，也能用历史工具读取单向工位的完整记录；之后的普通点名也会补上这些单向回答。伙伴与对话共用工作文件夹，所以「不读 `.starport/history` 下的对话存档」只是指令里的要求，不是技术隔离。长期记忆仍按房间里的记忆开关。

## 工作流

工作流是由阶段和位置组成的可复用模板。同一阶段的位置并行运行，每个阶段都能看到上一阶段的结果。某个位置可以设为验收位：它按工作流的验收标准检查之前的结果，最后给出通过或不通过。验收不通过时，工作流带着验收意见，从验收位之前的那一阶段重做，次数不超过你设定的重做次数（0–3）。

在 **工作流库** 里管理工作流；也可以把一次点名的执行顺序保存为新工作流。工作流可以挂到任何房间的任何对话上。挂载时为每个位置选一位伙伴；房间外的伙伴会自动加入房间。有位置空着时，工作流暂停。

## 触发与定时

每个挂载的工作流都有触发方式：

- **手动**：只在你启动时运行。
- **每天定时**：在设定时间运行，可以只选某几个星期几。
- **每隔一段时间**：每隔设定的分钟数或小时数运行。

定时在星港服务内部运行。关掉浏览器不会停止，但服务没开时不会运行。每个挂载可以分别设置：服务关闭期间错过的运行，在服务再次启动后补跑一次，还是跳过。定时运行可以暂停和恢复。

## 运行卡片

每次运行都会在对话里追加一张卡片。完成的运行默认折叠；失败或验收不通过的保持展开。在卡片上可以停止运行、查看每一步的过程，或点 **回复**，让你的下一条消息带上这次运行的结果。

每次运行，所有位置都在新的工位会话里开始，不读这个对话的历史。要在多次运行之间传递信息，请用台账或 **回复**。

## 台账

> **功能测试中：** 已经实现，也有自动测试覆盖，但还没有在实际工作中用过。

台账是工作流在多次运行之间保存的可选笔记本。默认关闭，按工作流分别开启。它参照 Anthropic 处理长时间运行 Agent 任务的做法，分为 PLAN、命题、只追加的 CHANGELOG 和检查项，每次运行后提交到 Git。

伙伴只能提议修改 PLAN，你确认后才生效。命题可以附带有截止日的预测，结果揭晓时用 Brier 分数计分。工作流可以提供 PLAN 模板。

台账保存在工作文件夹里的 `.starport/ledgers/`。同一文件夹里挂同一个工作流的对话共用一份台账。对话换到另一个文件夹时，原台账留在原处，之后使用目标文件夹的台账，没有就在下次运行时新建。旧版本数据目录里的私人台账不会自动搬迁。

## 考场

> **开发中：** 考场还没有完成，可能有问题，行为和考场文件夹的结构也可能还会变。

考场让伙伴在没有对话上下文的情况下各自独立做同一道题，方便你比较它们的答案。

1. 对话模型用 `starport_exam_propose` 提出考试：试卷文件夹、题目说明、最多八个考位（同一位伙伴可以坐几个考位）、可选的知识库，以及每个考位的时限。试卷最多 10,000 个文件、2 GB。对话里出现一张 **待开考** 卡片，这时还什么都没有复制。
2. 核对卡片。可以增减考位、把每个考位设为 **开卷** 或 **闭卷**、修改时限。点 **开考** 开始，或取消这次提议。考试绝不会自己开始。
3. 星港把试卷复制到桌面 `StarPortExams` 下的新文件夹里，每个考位一份，不复制 `.git`。开卷的考位另有放知识库的 `知识库/` 文件夹。
4. 所有考位同时作答。每位考生在新会话里只收到考场规则和题目说明，看不到这个对话、长期记忆、你在星港里的个人偏好和其他考位。各工具自己的全局指令，例如 `~/.claude/CLAUDE.md` 或 `~/.codex/AGENTS.md`，仍会照常加载。
5. 考位交卷后，星港会检查：试卷文件有没有被改或删、新增了哪些文件，以及有没有工具调用碰到原工作区、试卷或知识库原件、星港的数据文件夹或其他考位。

答卷和检查结果以考场卡片的形式回到对话。对话模型能看到它们，也能用历史工具读取每个考位的完整记录。考位不是沙箱：越界只能事后查出来，不能事前挡住。

## 房间里的记忆

在房间菜单里打开 **伙伴进出**。在每个房间里，每位伙伴有两个开关：

- **读长期记忆**（默认开）：伙伴会像对话模型一样收到相关的已确认记忆。
- **提记忆候选**（默认关）：伙伴可以提出新记忆。它的候选只能引用你的原话，保存前仍要你确认。

记忆怎样选取和确认，见 [共同记忆](shared-memory.md)。
