# 数据库结构

[English](../database-architecture.md) | 简体中文

星港使用关系型 SQLite。一个主数据库文件是 SQLite 的正常存储格式，并不意味着所有记录都塞在一张表或一段 JSON 里。本机、单用户的工作台不需要单独维护的数据库服务器，也不需要每个对话一个数据库。

## 表与关联

| 表 | 用途 | 关联 |
| --- | --- | --- |
| `groups` | 对话分组 | 被对话和项目引用 |
| `chats` | 标题、工作目录、工具和对话设置 | 可以属于一个分组 |
| `messages` | 用户和助手的消息、状态和原生执行细节 | 属于一个对话 |
| `sessions` | 原生会话映射和上下文游标 | 每个对话、每个工具一条映射 |
| `history_imports` | 原工具导入的来源和去重 | 指向导入后的对话 |
| `chat_transfers` | 会话文件摘要和导入去重 | 指向本地副本 |
| `projects` | 所选的工作文件夹 | 以具体文件夹为身份；子文件夹是独立的项目 |
| `history_archive_locations` | 对话历史存档的位置 | 记录更换工作目录后需要重试的旧位置 |
| `settings` | 应用和连接设置 | 按键读取 |
| `attachments` | 附件数据、元数据和副本位置 | 被消息引用 |
| `chat_summaries` | 压缩摘要及其覆盖范围 | 每个对话一条，随对话删除 |
| `companions` | 伙伴的身份、工具、模型和工作方式 | 通过成员关系加入房间 |
| `room_members` | 房间成员和记忆选项 | 引用分组和伙伴 |
| `room_calls` | 每个房间里，谁（主模型或伙伴）干活时可以调用哪位伙伴 | 引用分组和被调用的伙伴；伙伴离开房间时一并删除 |
| `workflows` | 可复用的阶段、位置和验收 | 挂载到对话上 |
| `workflow_mounts` | 挂在哪个对话、位置分配和触发方式 | 引用工作流和对话 |
| `companion_desks` | 伙伴在对话里的会话 | 隐藏的工位对话随父对话处理 |
| `prediction_scores` | 台账中到期预测的 Brier 分数 | 按挂载和命题保存 |

主键和复合主键标识记录与原生映射。数据库启用外键检查；消息按对话和创建时间建立索引。分组整理对话，与文件夹和模型相互独立。记忆和同步另有自己的关系表和索引；完整的当前结构请查看各个 schema 模块。

## 文件

- `.data/hub.sqlite`：本地主数据库。
- `.data/hub.sqlite-wal`：运行中的预写日志，可能包含尚未写回主文件的已提交数据。
- `.data/hub.sqlite-shm`：WAL 的共享内存索引。
- `.data/attachments/`：附件文件副本，与数据库中的元数据一起管理。
- 原工具的历史和用户的工作目录另行管理。

WAL 和 SHM 是运行中数据库的组成部分，不是垃圾。JSON 字段保存随工具变化的执行细节和工作流运行卡片的记录；对话标题、消息、分组和映射仍是独立的关系型记录。

## 备份与增长

逻辑导出请使用 **设置 → 连接与数据**。要直接复制数据库文件，先正常停止服务，或使用 SQLite 的一致性备份机制。不要只复制运行中的主文件而漏掉 WAL。

根据实测的查询开销增加索引、分页或维护。当多台机器访问或大量并发写入确实需要时，再考虑独立的数据库服务；不要以文件数量作为迁移的依据。

删除对话会移除该对话在星港中的记录、消息和映射，以及它自己的历史存档。附件、工作目录、原工具历史、导出和备份都会保留。相关文件需要另行检查并明确删除。普通的删除对话不包含自动检查点或 VACUUM。

参考：[SQLite 的适用场景](https://www.sqlite.org/whentouse.html)、[单文件数据库](https://www.sqlite.org/onefile.html)、[WAL](https://www.sqlite.org/wal.html)。
