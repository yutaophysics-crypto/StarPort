# 开放式记忆检索

[English](../memory-retrieval.md) | 简体中文

星港不会把你的兴趣归入一份允许的话题清单。已确认的记忆是可信的资料，而不是适用于每个请求的指令。

## 流程

1. 任务开始时，根据当前请求生成一份检索指引。简短的接续可以参照本对话中最近一条有实质内容、已送达的用户消息。只发送有限数量的候选 ID 和标题；不会自动加入任何记忆正文。
2. 当前 Harness 的模型用它认为相关的措辞调用 `starport_memory_search`。通用索引按文档频率、标题权重和长度，对多语言的字面词进行排序。没有领域名称或人工列举的同义词来限制访问。
3. 每次搜索最多返回 30 个候选标题和简短片段（默认 10 个）。由模型判断某条记录是否真的适用。例如，一条包含 AI 的股票偏好，对 AI 相关的查询来说是一个可能的字面命中，但它并不自动成为对某款 AI 游戏的偏好。
4. 遇到缺少同义词或换了语言的情况，模型会改写查询。空查询按标题分页浏览，类型筛选可以帮助发现与话题无关的沟通偏好。之后模型可以用 `starport_memory_read` 读取选中的 ID，并给出与本次任务相关的理由。
5. 任务中出现新的需要时，可以再次搜索和读取。范围、确认和冲突检查会重新进行；模型不能请求其他项目的记录。
6. 回答的回执记录实际的完整读取、版本和模型给出的理由。检索预览单独显示。新建候选记忆仍需要你之后确认。

## 职责与限制

- 星港负责存储、通用的候选排序、范围检查、预算和回执。当前项目的要求和明确保存的全局偏好，仍是由你编写的独立指令层。
- 当前的 Codex、Claude Code、Antigravity 或 DeepSeek 模型负责语义理解，并决定读取什么。这使用它正常的任务和工具轮次，不会另外调用付费的预检模型，也不需要新的厂商账号。
- 搜索索引是派生的本地数据。已确认正文的修改会让缓存的分词索引失效。共享文件夹同步传输的是权威记录；每台电脑各自建立索引。
- 候选、已删除、属于其他项目以及处于同步冲突中的记录都无法被搜索或读取。读取从不确认或修改记忆、文件、对话或厂商设置。
- 每个任务有 12,000 字符的检索预览预算和 9,000 字符的完整正文预算，最多 30 条不同的完整记录，每次调用最多八个 ID。工具错误和原生命令权限不可用都会被报告；不会修改任何全局权限设置。
- 这个版本没有向量或嵌入索引。在模型改写查询或浏览之前，字面检索可能漏掉不同的措辞或跨语言的等价说法。理由是模型的解释，不能证明它选得对，也不能证明它在最终回答里用了这条记忆。测试验证的是传输、范围、预算和回执的行为，而不是每个可能话题上的语义质量。

将来的语义或向量候选引擎可以在同样限定范围的搜索和读取接口之后替换本地排序器。这种扩展同样不需要话题清单。
