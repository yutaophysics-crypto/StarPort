# 项目级外部开发工具

点击输入框下方 **工作文件夹右侧的「外部工具」**，直接为当前项目添加工具安装文件夹。程序路径可选，但必须在安装文件夹内。**验证访问** 使用 Claude 同一层 Windows 沙箱读取目录和程序信息，不会启动构建。

**常用工具** 会记住本机在星港里添加过的工具名称、安装目录和程序路径，同一安装目录只保留一条最新记录。已有授权会自动出现在列表中；移除项目授权后，常用记录仍会保留。点击 **添加到当前项目** 才会为当前项目创建授权，其他项目不受影响。选用时重新校验实际路径和项目边界，已失效的路径需要手动重新添加。常用列表仅保存在本机，不会同步到其他设备。

当前接入原生 Windows 上的 Claude Code，使用 Codex Windows MXC 运行时。优先沿用已有隔离终端的运行时，也可使用本机已注册的原生 `codex.exe`。其他供应商继续遵循原工具权限。目录授权不会开放联网，也不会自动接入编辑器界面操作。

授权只属于当前工作文件夹，子文件夹是独立项目。隔离终端里安装目录只读，项目和 `.starport-claude-runtime` 缓存可写。临时目录、用户目录、npm 缓存、AppData、LocalAppData 都指向项目缓存。能读程序文件不代表完整程序能启动：Electron/Chromium 等运行时可能需要 MXC 中不可用的系统能力。**验证访问只证明能读取文件**，不能证明能启动或构建成功。不会自动解除沙箱，也不会自动向隔离终端开放原用户目录中的引擎登录和个人偏好。

## 本机兼容运行

> **功能测试中：** 本机兼容运行和常驻程序还没有在实际工作中用过。

已登记的 `.exe` 无法在沙箱中启动时，Claude 可请求 `mcp__starport_external_tools__run`。外部工具中的 **本机运行授权** 默认是 **每次询问**，启动前展示程序、原样参数、实际工作目录及运行方式。改为 **此项目始终允许** 后，Claude 在后续轮次中启动该项目登记的程序不再反复请求批准。设置只保存在本机、只作用于当前项目和程序，常用工具不会把它带给其他项目。随时改回询问可撤销后续自动启动；已运行的程序仍需单独关闭。Claude 自动审核或跳过权限模式不覆盖这个项目设置。

这是一次明确的权限例外：程序和子进程使用当前 Windows 用户权限，能访问本机文件、账号配置和网络。工作目录在项目中**不代表只能访问项目**。只批准可信程序和参数；程序加载的项目脚本、插件也会获得这些权限。Claude 的普通命令仍在 MXC 内执行；单纯添加目录不会自动获得本机运行授权。

启动器只执行当前项目登记的 `.exe`，不经 shell 拼接命令；批准后再次校验程序实际路径及目录联接。工作目录必须实际位于项目内，不能通过联接跳到外面。参数使用真实绝对路径，不能把 PowerShell 的 `StarPort:` 虚拟路径传给外部程序。默认成功退出码为 `[0]`，其他软件可提供官方定义的 `successExitCodes`。普通命令默认时限 120 秒、最长 15 分钟，完成或取消时清理进程树。返回真实退出码和长度受限的日志尾部，避免结果过大后被 Claude 转存到项目外而无法读取。

让 Claude 保持编辑器或服务运行时，使用 **`persistent: true`**。启动后返回程序 id，任务结束、停止后续对话任务或重启星港都不会关闭该程序。相同工具、参数和目录的常驻请求会复用已有实例。独立管理进程和 Windows Job 保留其子进程，即使应用启动器先退出也不会误关编辑器。磁盘日志限制长度；每个项目最多保持八个常驻程序。启动确认只表示进程活着，不表示工程导入完成或没有错误。

后续轮次可用 `mcp__starport_external_tools__list`、`stop` 管理，也可在外部工具里的 **常驻程序 → 关闭程序** 操作。关闭会终止本次管理的进程树，请先保存编辑器修改。控制使用唯一 Job 标识，不按旧 PID 杀进程；其他项目不可访问。移除工具授权前须先关闭该工具的常驻程序。状态和日志放在本机 `.data/external-applications`，不应作为可迁移授权分发。这会打开真实编辑器窗口；鼠标键盘自动操作仍需额外接入。

配置保存在本机 `.data/external-tools.json`，不放进项目或共同记忆，不应作为可迁移的授权分发。移动项目后需要重新添加工具。保存、启动和命令执行时检查实际路径；目录联接改变目标后必须重新授权。整盘、整个用户目录、星港和私有配置等宽泛目录不能作为工具安装目录添加。

Claude 获得额外目录和禁止编辑安装文件的规则；这些会话关闭原生命令工具，普通命令通过 SDK 内的星港隔离终端运行，完整应用可使用上面单独授权的通道。隔离终端不再依赖每轮单独启动的 stdio 进程和临时清单。私有的每轮设置副本保留原代理、浏览器 MCP 和明确配置的其他 MCP，结束后清理。授权或运行策略变化会让原生会话指纹失效，下一轮用星港已保存的历史建立新原生会话，聊天记录不会删除。

项目有对话或工作流任务时，不能修改或验证授权。加载更新也会等所有任务空闲，正在执行的任务保留原有权限。

## Cocos Creator

添加版本文件夹，例如 `C:\DevTools\Cocos\Creator\3.8.8`，程序填 `CocosCreator.exe` 的完整路径。在隔离终端阅读引擎文件；完整构建使用本机兼容运行。把本项目授权改为“此项目始终允许”即可免除重复批准。保持编辑器打开时，使用 `args: ["--project", "<实际工程路径>"]` 和 `persistent: true`。星港不会加入 Cocos 专属启动参数。

Creator 3.8 参数是 `--project <项目路径> --build "platform=web-desktop;debug=true"`，输出和日志放在项目内。Cocos 构建成功的退出码是 **36**。游戏本身仍需是有效的 Cocos 工程，目录授权不会转换游戏。参见 [Cocos 命令行发布](https://docs.cocos.com/creator/3.8/manual/zh/editor/publish/publish-in-command-line.html)。
