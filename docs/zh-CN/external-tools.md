# 项目级外部开发工具

点击输入框下方 **工作文件夹右侧的「外部工具」**，直接为当前项目添加工具安装文件夹。程序路径可选，但必须在安装文件夹内。**验证访问** 使用 Claude 同一层 Windows 沙箱读取目录和程序信息，不会启动构建。

**常用工具** 会记住本机在星港里添加过的工具名称、安装目录和程序路径，同一安装目录只保留一条最新记录。已有授权会自动出现在列表中；移除项目授权后，常用记录仍会保留。点击 **添加到当前项目** 才会为当前项目创建授权，其他项目不受影响。选用时重新校验实际路径和项目边界，已失效的路径需要手动重新添加。常用列表仅保存在本机，不会同步到其他设备。

当前接入原生 Windows 上的 Claude Code，使用 Codex Windows MXC 运行时。优先沿用已有隔离终端的运行时，也可使用本机已注册的原生 `codex.exe`。其他供应商继续遵循原工具权限。目录授权不改变终端原有网络策略；启用上述按服务划分策略的本机，普通命令使用正常网络。目录授权不会自动接入编辑器界面操作。

授权只属于当前工作文件夹，子文件夹是独立项目。隔离终端里安装目录只读，项目和 `.starport-claude-runtime` 缓存可写。临时目录、用户目录、npm 缓存、AppData、LocalAppData 都指向项目缓存。能读程序文件不代表完整程序能启动：Electron/Chromium 等运行时可能需要 MXC 中不可用的系统能力。**验证访问只证明能读取文件**，不能证明能启动或构建成功。不会自动解除沙箱，也不会自动向隔离终端开放原用户目录中的引擎登录和个人偏好。

## 常驻项目预览

> **功能测试中：** 已经实现，也有自动测试覆盖，但还没有在实际工作中大量使用。

已启用按服务划分 Claude 网络权限的 Windows 本机，Claude 获得 `mcp__starport_preview__start`、`list`、`stop`，没有外部应用授权的项目也可使用。`start` 接收项目内文件夹和可选端口（0 自动选择），实际连接检查通过后才返回本机网址。同一文件夹重复启动会复用正在运行的预览；其他服务占用的端口会保留。

预览使用星港登记的 Codex 运行时和 Node，在独立的只读项目文件沙箱中常驻。命令结束、对话换轮、MCP 断开、星港重启后仍可访问，用完须明确停止。它提供已构建 HTML/Cocos 页面的静态文件服务，支持资源 MIME 类型和音视频范围请求；不会执行项目脚本、编译构建或提供自定义后端。无需指定 Python 安装位置或增加通用本机程序权限。点号私有文件、星港私有数据、目录列表、路径穿越和越界目录联接均不可访问，只监听本机回环地址。

在 **外部工具 → 项目预览** 中可启动、打开或停止。操作仅属于当前项目，任务运行时也能使用；星港重载后可继续管理原服务，每个项目最多同时运行八个。普通命令工具仍是一次性的，其中启动的后台子进程会随命令结束而关闭。已构建网页使用预览工具；完整桌面程序和自定义开发后端使用另行授权的常驻应用通道。Claude 客户端防火墙保护和 DSH 网络例外保持不变。

## 按服务划分网络权限（Windows）

> **功能测试中：** 已经实现，也有自动测试覆盖，但还没有在实际工作中大量使用。

`node scripts/setup-claude-network.mjs --proxy http://127.0.0.1:<端口>`（填 Claude 客户端必须使用的本机 HTTP 代理）安装仓库自带的普通开发终端与 Git 身份/认证助手，生成本机 `.data/claude-network-policy.json`。用管理员 PowerShell 运行 `scripts/claude-network-firewall.ps1 -Mode Apply` 后，再运行 `node scripts/setup-claude-network.mjs --activate` 并在全部任务空闲时重新加载星港。重复安装会保留代理地址并重新盘点客户端，不依赖某次会话或日期命名的临时目录。

此模式只让实际 Claude 客户端、SDK 独立副本及专用浏览器固定走代理并禁止公网直连；DSH 主程序、普通终端的 Git、下载器和构建子进程使用正常网络，项目文件隔离继续生效。DSH 自己发送的 HTTP 请求不受这项 Claude 客户端限制；它启动的独立 Claude 可执行文件仍须单独覆盖。安装清单用 normalPrograms 标记 DSH，管理员 Apply 只撤销其路径对应的本工具规则；后续重新安装也不会把 DSH 主程序加回保护清单。完整 Creator、微信开发者工具等通过已登记应用的本机运行通道启动；原项目授权、逐次确认/始终允许、取消和超时清理继续生效。Cocos 构建成功码为 `36`，不能把进程活着当作构建成功。

普通终端显式允许写入项目自身的 `.git`，支持初始化仓库、暂存、提交及 fetch 元数据；`.git` 目录联接不会获得额外写权限。星港私有数据、只读工具安装目录和其他受保护项目路径保留原有限制，Git 操作仍在文件沙箱中执行。真实 Windows Git 回归测试：将 `STARPORT_MXC_TEST_EXECUTABLE` 设为已登记的原生 `codex.exe`，运行 `node scripts/run-tests.mjs tests/claude-git.test.mjs`；可用 `STARPORT_GIT_TEST_EXECUTABLE` 指定 Git for Windows。测试只使用临时仓库和通过本机回环 HTTP 服务访问的本地裸仓库远端。

星港在启动受保护的 Claude 客户端前核对有效防火墙规则；发现新 Claude 副本或缺失规则时阻止启动，须重新执行管理员 Apply。规则按实际可执行文件路径匹配；未登记的新客户端、改名副本、自写的 Claude API 脚本及星港外独立启动的程序不能自动视为已覆盖。新增这类组件须先登记并核验。代理软件里针对 Claude 域名的固定线路规则只是补充，不代替客户端防火墙。

`STARPORT_ISOLATED_RUNNER` 是旧的整条命令树隔离接入；启用上述本机策略后，所有 Claude 项目均使用仓库提供的同一个普通终端，包括没有外部工具授权的项目。专用浏览器安装与原有规则保留。

本机若为 `starport_workspace` 的 MCP 配置设置了 `env.STARPORT_ISOLATED_RUNNER`（隔离命令运行器的绝对脚本路径），外部工具项目与普通终端沿用同一个运行器；其 `command` 必须是已安装运行时的绝对路径。命令、工作目录、超时与已授权安装目录通过 JSON 标准输入传入，目录保持只读。配置失效时直接失败，不切换到宿主执行或另一套网络策略。设置 `env.STARPORT_ALLOW_HOST_TOOLS="0"` 可禁止模型的本机运行通道，即使项目以前记住过本机授权；原授权记录不会删除。

对话主模型可用 `starport_runtime_status` 查询任务数量和本对话伙伴步骤，用 `starport_reload_when_idle` 安排所有任务及远程工作器空闲后加载已安装更新；无需给终端开放完整的本机管理 HTTP 接口。这两个能力不提供通用 API、命令执行或其他对话正文。

## 本机兼容运行

> **功能测试中：** 本机兼容运行和常驻程序还没有在实际工作中用过。

已登记的 `.exe` 无法在沙箱中启动时，Claude 可请求 `mcp__starport_external_tools__run`。外部工具中的 **本机运行授权** 默认是 **每次询问**，启动前展示程序、原样参数、实际工作目录及运行方式。改为 **此项目始终允许** 后，Claude 在后续轮次中启动该项目登记的程序不再反复请求批准。设置只保存在本机、只作用于当前项目和程序，常用工具不会把它带给其他项目。随时改回询问可撤销后续自动启动；已运行的程序仍需单独关闭。Claude 自动审核或跳过权限模式不覆盖这个项目设置。

这是一次明确的权限例外：程序和子进程使用当前 Windows 用户权限，能访问本机文件、账号配置和网络。工作目录在项目中**不代表只能访问项目**。只批准可信程序和参数；程序加载的项目脚本、插件也会获得这些权限。Claude 的普通命令仍在 MXC 内执行；单纯添加目录不会自动获得本机运行授权。

启动器只执行当前项目登记的 `.exe`，不经 shell 拼接命令；批准后再次校验程序实际路径及目录联接。工作目录必须实际位于项目内，不能通过联接跳到外面。参数使用真实绝对路径，不能把 PowerShell 的 `StarPort:` 虚拟路径传给外部程序。默认成功退出码为 `[0]`，其他软件可提供官方定义的 `successExitCodes`。普通命令默认时限 120 秒、最长 15 分钟，完成或取消时清理进程树。返回真实退出码和长度受限的日志尾部，避免结果过大后被 Claude 转存到项目外而无法读取。

让 Claude 保持编辑器或服务运行时，使用 **`persistent: true`**。启动后返回程序 id，任务结束、停止后续对话任务或重启星港都不会关闭该程序。相同工具、参数和目录的常驻请求会复用已有实例。独立管理进程和 Windows Job 保留其子进程，即使应用启动器先退出也不会误关编辑器。磁盘日志限制长度；每个项目最多保持八个常驻程序。启动确认只表示进程活着，不表示工程导入完成或没有错误。

后续轮次可用 `mcp__starport_external_tools__list`、`stop` 管理，也可在外部工具里的 **常驻程序 → 关闭程序** 操作。关闭会终止本次管理的进程树，请先保存编辑器修改。控制使用唯一 Job 标识，不按旧 PID 杀进程；其他项目不可访问。移除工具授权前须先关闭该工具的常驻程序。状态和日志放在本机 `.data/external-applications`，不应作为可迁移授权分发。这会打开真实编辑器窗口；鼠标键盘自动操作仍需额外接入。

配置保存在本机 `.data/external-tools.json`，不放进项目或共同记忆，不应作为可迁移的授权分发。移动项目后需要重新添加工具。保存、启动和命令执行时检查实际路径；目录联接改变目标后必须重新授权。整盘、整个用户目录、星港和私有配置等宽泛目录不能作为工具安装目录添加。

Claude 获得额外目录和禁止编辑安装文件的规则；这些会话关闭原生命令工具，普通命令通过 SDK 内的星港隔离终端运行，完整应用可使用上面单独授权的通道。隔离终端不再依赖每轮单独启动的 stdio 进程和临时清单。私有的每轮设置副本保留原代理、浏览器 MCP 和明确配置的其他 MCP，结束后清理。授权或运行策略变化会让原生会话指纹失效，下一轮用星港已保存的历史建立新原生会话，聊天记录不会删除。

项目有对话或工作流任务时，不能修改或验证授权。加载更新也会等所有任务空闲，正在执行的任务保留原有权限。

## Cocos Creator

添加版本文件夹，例如 `C:\DevTools\Cocos\Creator\3.8.8`，程序填 `CocosCreator.exe` 的完整路径。在隔离终端阅读引擎文件；完整构建使用本机兼容运行。把本项目授权改为“此项目始终允许”即可免除重复批准。保持编辑器打开时，使用 `args: ["--project", "<实际工程路径>"]` 和 `persistent: true`。星港不会加入 Cocos 专属启动参数。

Creator 3.8 参数是 `--project <项目路径> --build "platform=web-desktop;debug=true"`，输出和日志放在项目内。Cocos 构建成功的退出码是 **36**。游戏本身仍需是有效的 Cocos 工程，目录授权不会转换游戏。参见 [Cocos 命令行发布](https://docs.cocos.com/creator/3.8/manual/zh/editor/publish/publish-in-command-line.html)。
