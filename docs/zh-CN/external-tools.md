# 项目级外部开发工具

点击输入框下方 **工作文件夹右侧的「外部工具」**，直接为当前项目添加工具安装文件夹。程序路径可选，但必须在安装文件夹内。**验证访问** 使用 Claude 同一层 Windows 沙箱读取目录和程序信息，不会启动构建。

**常用工具** 会记住本机在星港里添加过的工具名称、安装目录和程序路径，同一安装目录只保留一条最新记录。已有授权会自动出现在列表中；移除项目授权后，常用记录仍会保留。点击 **添加到当前项目** 才会为当前项目创建授权，其他项目不受影响。选用时重新校验实际路径和项目边界，已失效的路径需要手动重新添加。常用列表仅保存在本机，不会同步到其他设备。

当前接入原生 Windows 上的 Claude Code，使用 Codex Windows MXC 运行时。优先沿用已有隔离终端的运行时，也可使用本机已注册的原生 `codex.exe`。其他供应商继续遵循原工具权限。目录授权不会开放联网，也不会自动接入编辑器界面操作。

授权只属于当前工作文件夹，子文件夹是独立项目。安装目录可读、可运行，不能写入；项目和 `.starport-claude-runtime` 缓存可写。临时目录、用户目录、npm 缓存、AppData、LocalAppData 都指向项目缓存。工具需要其他位置时返回真实错误，不会自动解除沙箱，也不会自动开放原用户目录中的引擎登录和个人偏好。

配置保存在本机 `.data/external-tools.json`，不放进项目或共同记忆，不应作为可迁移的授权分发。移动项目后需要重新添加工具。保存、启动和命令执行时检查实际路径；目录联接改变目标后必须重新授权。整盘、整个用户目录、星港和私有配置等宽泛目录不能作为工具安装目录添加。

Claude 获得额外目录和禁止编辑安装文件的规则；这些会话关闭原生命令工具，统一通过星港隔离终端运行命令。私有的每轮设置副本保留原代理、浏览器 MCP 和明确配置的其他 MCP，结束后清理。授权变化会让原生会话指纹失效，下一轮用星港已保存的历史建立新原生会话，聊天记录不会删除。

项目有对话或工作流任务时，不能修改或验证授权。加载更新也会等所有任务空闲，正在执行的任务保留原有权限。

## Cocos Creator

添加版本文件夹，例如 `C:\DevTools\Cocos\Creator\3.8.8`，程序填 `CocosCreator.exe` 的完整路径。让 Claude 阅读引擎文件，通过 `mcp__starport_workspace__run_command` 构建。Windows GUI 程序应使用 `Start-Process -Wait -PassThru -WindowStyle Hidden` 或 Node 的 `child_process.spawnSync` 等待退出；直接调用可能提前返回。

Creator 3.8 参数是 `--project <项目路径> --build "platform=web-desktop;debug=true"`，输出和日志放在项目内。Cocos 构建成功的退出码是 **36**。游戏本身仍需是有效的 Cocos 工程，目录授权不会转换游戏。参见 [Cocos 命令行发布](https://docs.cocos.com/creator/3.8/manual/zh/editor/publish/publish-in-command-line.html)。
